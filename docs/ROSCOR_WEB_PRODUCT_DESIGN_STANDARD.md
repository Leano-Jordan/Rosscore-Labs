# Rosscore Web Product Design Standard

## Purpose

This is the company-level web craft standard for Rosscore commercial website Directors.

**Rosscore standardizes quality, not appearance.**

The reusable system is a product/design/engineering engine. It is not a house visual template.

Project Directors must preserve their project's identity, customer context, architecture and evidence while applying this standard.

---

## Core pipeline

Every new or substantially redesigned commercial website should progress through:

**BUSINESS → MARKET + CUSTOMER → POSITIONING → DESIGN DNA → UX ARCHITECTURE → VISUAL SYSTEM → COMPONENTS → UNIQUE SITE**

Do not begin with a generic visual prompt.

---

## Design DNA gate

Before major visual implementation, establish a compact Design DNA profile from current project evidence.

At minimum define:

- brand personality
- target customer's expectations and anxieties
- market position
- competitive visual environment
- visual language
- layout rhythm
- navigation behaviour
- hero/composition strategy
- CTA language and hierarchy
- typography character
- shape language
- colour behaviour
- imagery/art direction
- interaction/motion language
- trust/proof presentation

The profile must explain **why** the visual system fits the business.

Design DNA is project-specific. It must not be copied from another Rosscore project merely because that project performed well.

---

## Reusable-core rule

Reuse:

- engineering patterns
- accessibility foundations
- responsive techniques
- conversion instrumentation
- content/data separation
- SEO foundations
- testing/QA methods
- proven information-architecture patterns
- deployment practices
- service/page schemas where the business category warrants them

Do not automatically reuse:

- colour palettes
- typography pairings
- hero layouts
- section ordering
- card shapes
- button styling
- decorative effects
- imagery style
- motion language
- brand voice

**Reusable architecture must produce different-looking products when the businesses require different experiences.**

---

## Anti-Slop Check

Before accepting a major composition, compare it against:

1. the project's Design DNA;
2. the current site's actual customer journey;
3. relevant contemporary commercial competitors;
4. recent Rosscore sites.

Reject or mutate the composition when it relies on generic patterns without a product reason.

Warning signs include:

- generic centred hero with two pill CTAs
- repeated three/four-card grids
- excessive rounded cards or pills
- generic SaaS/minimalist/editorial styling applied without evidence
- gradients, glows, blobs or glass effects used as decoration
- identical section rhythm from top to bottom
- giant headline + tiny supporting copy as an automatic formula
- stock/AI imagery presented as proof
- fake or unsupported reviews, counters, credentials or guarantees
- vague AI marketing language
- animation added only to make the site feel premium
- a visual composition substantially similar to another Rosscore site without a business reason

Similarity is a warning, not a ban. A repeated pattern is acceptable when it is the strongest evidence-based solution.

---

## Distinctiveness test

For each major page, ask:

- Could a competitor have generated this from the same generic AI prompt?
- Could this layout belong to a different industry without meaningful changes?
- Does the composition express the actual business or merely a design trend?
- Is the strongest visual element supporting the strongest business message?
- Does the mobile composition remain intentional?
- Is the site recognizably this client rather than recognizably Rosscore?

If the answer exposes generic composition, redesign before polishing.

---

## Exploration rule

For a major redesign or a new site's primary visual direction, consider 2–3 materially different directions before committing.

Possible directions include:

- editorial/art-directed
- conversion-led/utility-first
- asymmetric/composition-led
- premium/restrained
- bold/typographic
- image-led/immersive

The selected direction must win on product outcome, audience fit, evidence, accessibility, performance and maintainability.

Novelty is not the goal. Distinctive fitness is.

---

## Commercial baseline

Every substantial commercial page must establish:

- clear visitor purpose
- clear value proposition
- deliberate conversion path
- evidence-backed trust
- meaningful content hierarchy
- responsive composition
- semantic/accessibility foundations
- performance-aware media handling
- production-aware SEO foundations
- easy content/brand replacement
- no fabricated business claims

---

## Director behaviour

When a user says continue, the web Director should keep moving through safe, high-value work rather than waiting for micro-instructions.

Priority order:

**conversion impact → broken UX → visual quality → accessibility → performance → maintainability → polish**

Reports should distinguish:

- source verified
- execution verified
- browser verified
- device verified
- client verified

Never upgrade evidence by assumption.

---

## Boundary

This standard is a company-level discipline pack.

A project Director remains the authority for its own repository and must not import another project's branding, requirements, architecture or historical assumptions merely because the standard references those projects.
